# دليل المعمارية والهيكلة الشاملة للمشروع (AI Context & Architecture Guide)

> **تنبيه لأي نموذج ذكاء اصطناعي (AI Prompt / Context Injection):**
>
> هذا الملف هو المرجع الأساسي الشامل والوحيد لهذا المشروع. اقرأ هذا الملف بعناية؛ فهو يشرح فلسفة البناء، بنية الملفات، تدفق البيانات، النماذج البيانية، والمواقع الدقيقة للتعديل البرمجي دون الحاجة لطلب ملفات المشروع كاملة.

## 1. نظرة عامة وفلسفة المشروع (Core Philosophy)

* **النوع:** متجر إلكتروني عام وقابل للتخصيص لأي نشاط تجاري (مع دعم متخصص لمتاجر الألبسة والأزياء).

* **التقنيات المستخدمة:** **Vanilla Web Technologies** فقط:

  * **HTML5** نظيف ومتوافق بالكامل.

  * **CSS3 خالص** يعتمد على CSS Variables وتصميم متجاوب بالكامل (Mobile-First / Responsive).

  * **Vanilla JavaScript (ES6+)** بدون أي أطر عمل (No React, No Vue, No Next.js).

  * **بدون أدوات بناء (No Build Tools / No Bundlers / No Webpack / No Vite):** لا توجد حزم Node.js أو `npm`. المشروع يعمل بمجرد فتح أي ملف HTML في المتصفح أو رفعه كاستضافة ثابتة (Static Hosting).

* **لغة الواجهة والاتجاه:** اللغة العربية كاملة بنظام اتجاه اليمين إلى اليسار (`dir="rtl"`).

* **النطاق العام (Global Scope Architecture):** لا يتم استخدام نظام حزم جافاسكريبت (`import` / `export`)، بل يتم تحميل الملفات عبر وسوم `<script>` عادية، وتُعرَّف الكائنات والدوال مركزياً في النطاق العام (`window.Store`, `window.STORE_CONFIG`, `iconSvg()`, إلخ).

## 2. آليات التخزين والربط السحابي (Data & Infrastructure Stack)

يعمل المشروع وفق نمط **Hybrid Data Layer (محلي + سحابي اختياري)**:

1. **التخزين المحلي الافتراضي (`localStorage`):**

   * يعمل المتجر فوراً بشكل كامل 100% دون أي خوادم أو إعدادات عبر التخزين المحلي للمتصفح.

2. **المزامنة السحابية (Firebase Realtime Database - اختياري):**

   * في حال ملء الرابط في الإعدادات، يتم مزامنة المنتجات، الأقسام، الإعلانات، والطلبات سحابياً بين كل الأجهزة.

   * **تقنية التحميل حسب الطلب (Section-based & Lazy Loading):** لتوفير استهلاك البيانات، لا يتم سحب كامل كتالوج المنتجات في الواجهة العامة دفعة واحدة، بل يتم تحميلها وتصفيتها مجزأة مع ترقيم صفحات (Pagination) واستخدام Caching لمدة 15 دقيقة.

3. **المصادقة والأمان (Firebase Authentication):**

   * لوحة الإدارة (`admin.html`) محمية عبر حسابات أدمن حقيقية بواسطة Firebase Auth (Email & Password)، مع التحقق من القائمة البيضاء (`STORE_CONFIG.adminEmails`).

4. **خدمة الصور وCDN (ImgBB + ImageKit):**

   * **ImgBB:** رفع الصور مباشرة من لوحة التحكم للمنتجات، الألوان، الأقسام، والإعلانات عبر واجهة برمجة التطبيقات (API).

   * **ImageKit:** طبقة CDN اختيارية لمعالجة الصور وتصغير أبعادها وتحويلها تلقائياً إلى صيغة `WebP` عالية الكفاءة عبر الروابط المحولة.

5. **نظام الطلب عبر واتساب (WhatsApp Checkout Pipeline):**

   * لا توجد بوابات دفع إلكتروني معقدة؛ يتم تجميع معلومات التوصيل عبر نافذة منبثقة، ثم فتح محادثة واتساب موجهة لرقم المتجر مع صياغة رسالة مفصلة بالمنتجات، الكميات، الألوان، المقاسات، والأسعار.

## 4. ترتيب تحميل السكربتات الإلزامي (Script Load Order)

نظراً لأن المشروع يعتمد على النطاق العام، فإن ترتيب وسوم `<script>` في ملفات HTML حرج للغاية ويجب الحفاظ عليه دائماً:

```
<!-- 1. الإعدادات المركزية -->
<script src="js/config.js"></script>

<!-- 2. مكتبة الأيقونات -->
<script src="js/icons.js"></script>

<!-- 3. مكتبات Firebase (SDKs) -->
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-app-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-auth-compat.js"></script> <!-- في صفحات الأدمن والدخول فقط -->
<script src="https://www.gstatic.com/firebasejs/10.12.2/firebase-database-compat.js"></script>

<!-- 4. طبقة البيانات الأساسية -->
<script src="js/store.js"></script>

<!-- 5. دوال الواتساب وتنسيق الأسعار -->
<script src="js/whatsapp.js"></script>

<!-- 6. البنية العامة (الهيدر، الفوتر، القوائم) -->
<script src="js/app.js"></script>

<!-- 7. منطق الصفحة المتخصصة (حسب كل صفحة) -->
<!-- مثال: products.js في صفحة المتجر، cart.js في السلة، admin.js و auth.js في لوحة التحكم -->

```

## 6. الأنظمة البرمجية وآليات العمل (Core Systems Deep-Dive)

### 6.1 محرك المخزون ومصفوفة الخيارات (Variant Matrix Engine)

* **بناء المفتاح:** يتم توليد المفتاح الداخلي لمخزون كل تركيبة بواسطة دالة `inventoryKey(color, size)` داخل `store.js` بصيغة:

  * لون ومقاس: `"أسود||M"`

  * لون فقط: `"أسود||_"`

  * مقاس فقط `"_||M"`

* **احتساب المخزون الإجمالي:** دالة `Store.getTotalStock(product)` تجمع كميات مصفوفة `inventory`. إذا لم يحتوِ المنتج على ألوان أو مقاسات، تعتمد الدالة على الحقل العددي البسيط `product.stock`.

* **التحقق من توفر المنتج:** الدالة المعيارية المعتمدة هي `Store.isProductAvailable(product)` والتي تتحقق من:
  `(product.available === true && Store.getTotalStock(product) > 0)`.

### 6.2 نظام تصفح وتفرع الأقسام في المتجر (Category Navigation)

* في صفحة `products.html`:

  * شريط الأزرار العلوي (`#filterCategories`) يعرض الأقسام الرئيسية بالإضافة لفلاتر: الكل، المميزة، العروض، ووصل حديثاً.

  * عند اختيار قسم رئيسي يمتلك تفرعات (`subCategories`)، يظهر شريط فرعي منساب بنمط الرقائق (`#subCategoryScroller`) أسفل التبويبات مباشرة لعرض التفرعات التابعة له مع زر "كل التفرعات".

### 6.3 دورة حياة إتمام الطلب عبر واتساب (WhatsApp Checkout Flow)

1. يضغط العميل على "طلب عبر واتساب" في صفحة المنتج أو "إكمال الطلب" في السلة.

2. تتحقق دالة `isWhatsAppConfigured()` من وجود رقم هاتف للمتجر مسجل في الإعدادات؛ فإن لم يوجد يتم عرض تنبيه (Toast).

3. تفتح نافذة مودال منبثقة تفاعلية `showDeliveryModal(callback)` لجمع بيانات العنوان: (المحافظة، المنطقة، أقرب نقطة دالة، ورقم هاتف الزبون).

4. بعد الإرسال، يُسجل الطلب محلياً وفي Firebase كأرشيف استرشادي عبر `Store.logOrder()`.

5. تُصاغ رسالة نصية مهيكلة ومرتبة برموز تعبيرية تحتوي على أسماء المنتجات، ألوانها، مقاساتها، أسعارها، الإجمالي، وبيانات التوصيل.

6. يُفتح الرابط في علامة تبويب جديدة عبر الرابط المنسق: `https://wa.me/{number}?text={encodedText}`.

### 6.4 منظومة رفع ومعالجة الصور (Image Processing Pipeline)

تتم عملية رفع الصور في لوحة الأدمن عبر الدالة `uploadToImgBB(file, isBanner)` داخل `admin.js`:

1. تُرسل الصورة لـ ImgBB API وتُستخرج الرابط المباشر.

2. يتم فحص `STORE_CONFIG.imageKitEndpoint`:

   * إذا كان معرّفاً: يتم تحويل مسار الصورة إلى رابط CDN المحسّن مع وسائط التحجيم وضبط الجودة والتحويل إلى صيغة WebP (`tr:w-800,q-80,f-auto` للصور العادية، و`tr:w-1200,q-90,f-auto` لإعلانات السلايدر).

   * إذا كان فارغاً: يُستخدم رابط ImgBB الأصلي دون مشاكل.

## 7. دليل تعديل الميزات: «ما هو الملف الواجب تعديله؟» (Where to Edit Guide)

استخدم هذا الجدول لتحديد الملفات المسؤولة عن أي تعديل مطلوب مباشرة:

| **نوع التعديل المطلوب** | **الملفات المسؤولة** | **ملاحظات وتوجيهات برمجية** | 
| **تغيير الألوان الرئيسية، الخطوط، أو المسافات** | `css/style.css` | عدّل المتغيرات في `:root` بأعلى الملف (مثل `--olive-700`, `--sand-500`, `--cream`, `--radius-lg`). | 
| **تعديل شكل بطاقة المنتج أو شارات العروض (Badges)** | `js/products.js` و `index.html` | ⚠️ **تنبيه:** دالة بناء بطاقة المنتج مكررة في الملفين (`renderProductCard` في `products.js` و `renderHomeProductCard` داخل سكربت `index.html`). يجب مزامنة التعديل في الاثنين. | 
| **تعديل نص ورسالة الواتساب أو بيانات التوصيل** | `js/whatsapp.js` | عدّل دالة `showDeliveryModal` لتعديل حقول العنوان، ودالتي `buildProductWhatsAppLink` و `buildCartWhatsAppLink` لتغيير نص وتنسيق الرسالة. | 
| **إضافة وسيلة تواصل اجتماعي جديدة (مثل سناب شات، يوتيوب)** | `admin.html` + `admin.js` + `store.js` + `app.js` + `contact.html` + `index.html` | أضف الحقل في نموذج الإعدادات (`admin.html`)، احفظه في `admin.js`، وقم برسمه في الفوتر (`app.js`) وصفحة التواصل. | 
| **إضافة أيقونة SVG جديدة للنظام** | `js/icons.js` | أضف مسار الأيقونة داخل كائن `ICONS` كرمز SVG خالص، ثم استخدمها عبر `iconSvg("your-icon-key")`. | 
| **تعديل طريقة حساب المخزون أو منطق السلة** | `js/store.js` و `js/cart.js` | تقع جميع حسابات المخزون في `store.js` (`getVariantStock`, `getTotalStock`, `isProductAvailable`). | 
| **تعديل القائمة الجانبية (Sidebar Drawer) أو البحث الفوري** | `js/app.js` | دوال `renderSidebarNav`, `toggleSidebar`, و `initGlobalSearch`. | 
| **تعديل سلايدر الإعلانات في الصفحة الرئيسية** | `index.html` | الدالة `renderAdsSlider()` أسفل الصفحة، وتنسيقاته في `style.css`. | 
| **تعديل خيارات إضافة وتعديل المنتج في لوحة التحكم** | `admin.html` و `js/admin.js` | المودال `#productModal` في HTML، والدوال `openProductModal`, `renderColorsList`, `renderInventoryGrid`, و `saveProductForm` في JS. | 
| **تغيير عدد المنتجات في كل صفحة (Pagination Size)** | `js/products.js` | المتغير `SHOP_PAGE_SIZE = 20`. | 
| **تعديل بريد الأدمن أو مفاتيح الربط السحابي** | `js/config.js` | المتغير `STORE_CONFIG` (مفاتيح Firebase، البريد المسموح به، ImgBB، ImageKit). | 

## 8. محاذير برمجية حرجة للذكاء الاصطناعي (Critical AI Gotchas & Rules)

1. **إياك واستخدام وحدات المعالجة الحديثة (No ES Modules):** لا تقم نهائياً بكتابة `import ... from ...` أو `export default` داخل ملفات السكربت؛ فالمتصفح يقرأ الملفات كسكربتات عادية في النطاق العالمي.

2. **ازدواجية كود بطاقات الصفحة الرئيسية:** كود رسم بطاقة المنتج والإضافة السريعة للسلة موجود في `js/products.js` ومستنسخ أيضاً في وسم `<script>` داخل `index.html`. إذا عدلت أحدهما دون الآخر ستفقد الواجهة اتساقها.

3. **توليد الواجهات عبر سلاسل النصوص (Template Strings):** يتم رسم واجهات المتجر واللوحة عبر تجميع نصوص HTML في جافاسكريبت؛ تأكد من سلامة إغلاق الوسوم وعزل علامات التنصيص.

4. **تجاوز ذاكرة التخزين المؤقت للمتصفح (Cache Busting):** تستخدم روابط ملفات CSS و JS معاملات إصدار (مثل `style.css?v=34`). عند إجراء تعديلات هيكلية تتطلب ظهوراً فورياً لدى العميل، احرص على رفع رقم الإصدار في ملفات HTML المستدعية.

5. **مفتاح سطر السلة (`itemKey`):** تذكّر دائماً أن عنصر السلة ليس مجرد `productId`؛ بل مفتاح مركب (`prd_id|c:Color|s:Size`) لضمان عدم دمج المنتجات ذات الخيارات المختلفة في سطر واحد.

6. **احترام قواعد CSS و Tailwind:** لا توجد مكتبة Tailwind بالمشروع؛ التنسيقات تعتمد كلياً على فئات مخصصة مسجلة في `style.css`. استخدم أسماء الفئات الموجودة مسبقاً (مثل `.btn`, `.btn-primary`, `.btn-outline`, `.btn-sm`, `.card`, `.field`, `.pill`) للحفاظ على هوية الموقع المتناسقة.

**نهاية دليل المعمارية — هذا الدليل يمثل الحالة التشغيلية والبرمجية الكاملة للمشروع.**
